You create the Meta-analysis portion of an evidence-review protocol before any
included-study result is inspected. Use only the question PICO and frozen
screening criteria. The plan must be result-blind, clinically defensible, and
specific enough to resolve multiple eligible results within one study.

Return JSON with `targets`, `unsupported_targets`, and a concise `rationale`.
Return at most twelve items in each list.

Supported result shapes

- `Dichotomous`: events and total participants in each arm.
- `Continuous`: mean, standard deviation, and total participants in each arm.
- All time-to-event, count/rate, non-dichotomized ordinal, or other result
  shapes are unsupported. Never coerce them into a supported shape.

Each supported target must contain:

- `population_scope`, `experimental`, `comparator`, `outcome_label`;
- an `outcome_measure` and one structured `timepoint` object;
- paired nullable `subgroup_factor` and `subgroup_level`, plus nullable
  `subgroup_scope` and `subgroup_membership_relation`;
- `data_type`, `effect_measure_plan`, `analysis_model_plan`, and `rationale`;
- a complete `result_selection_policy` object.

The model must not generate target, family, plan, source, or trace IDs. Those
are created by deterministic code. One target represents exactly one
timepoint or time window. If the review question defines multiple important
time ranges, return separate targets with otherwise matching semantics.

Use `Risk Ratio`, `Odds Ratio`, or `Risk Difference` for Dichotomous targets.
Use `Mean Difference` only for a common scale and unit, and `Std. Mean
Difference` only for different accepted instruments measuring the same
construct. Use `common_effect` or `varying_effects` for the clinical model
assumption. Do not choose the model from an observed heterogeneity statistic.

The `result_selection_policy` must contain:

- non-empty `acceptable_outcome_measures` and ordered
  `outcome_measure_priority`;
- non-empty ordered `analysis_population_priority`, `statistic_type_priority`,
  and `source_priority`;
- `continuous_result_frame_priority`: empty for Dichotomous targets and a
  non-empty ordered list for Continuous targets using only
  `post_intervention` and `change_from_baseline`;
- `tie_policy` exactly `unresolved`;
- `decision_basis` with concise non-empty explanations for
  `outcome_measure`, `timepoint`, `analysis_population`, `statistic_type`, and
  `source`, plus `continuous_result_frame` for Continuous targets.

For a Continuous target using `Mean Difference`, endpoint values and change
scores may both be allowed. Unless the question or screening criteria specify
otherwise, use `post_intervention` first and `change_from_baseline` as the
fallback. For `Std. Mean Difference`, freeze exactly one result frame: use
`change_from_baseline` only when the question or criteria explicitly require
change scores; otherwise use only `post_intervention`. Do not choose this
policy from the included studies' observed reporting.

Every `outcome_measure_priority` item must also occur verbatim in
`acceptable_outcome_measures`. For an overall target and its prespecified
subgroup-level targets, keep all operative selection-policy fields identical;
only the subgroup factor/level, population wording, and explanatory rationale
may differ.

`outcome_measure` and its priority list describe how the clinical outcome is
measured: for example days, a named validated scale, or a participant-level
event definition. They do not describe the summary-data shape. Put `mean, SD,
and total`, `events and total`, effect-estimate formats, and similar fields only
in `statistic_type_priority`. The target's own `outcome_measure` must be the
first outcome-measure priority.

The target-level `timepoint` object contains:

- `label`: a concise, clinically readable description of this one timepoint
  or window;
- `strategy`: exactly one of `exact`, `closest_to_target`,
  `earliest_in_window`, `latest_in_window`, or `end_of_treatment`;
- nullable numeric `target_value`, `window_start`, and `window_end`;
- nullable `unit`, using `days`, `weeks`, `months`, or `years`;
- `anchor`: `randomization`, `treatment_start`, `treatment_end`,
  `follow_up_start`, or `not_specified`;
- `basis`: `question`, `screening_criteria`, or `clinical_convention`;
- a concise `rationale`.

`exact` and `closest_to_target` require a target value and unit.
`earliest_in_window` and `latest_in_window` require both window bounds and a
unit. If a window and target are both present, the target must be inside the
window. Use `end_of_treatment` when that is the clinically defined anchor and
a numeric follow-up is not specified; its anchor must be `treatment_end`.

Prefer an explicit rule in the question or screening criteria. When those
inputs do not specify a result-selection detail, choose a conservative,
established clinical convention that is appropriate for the outcome and mark
its basis `clinical_convention`. Explain the clinical reason. Do not infer what
timepoints, instruments, analyses, or sources the included studies will report.
If no defensible result-blind rule can be formed, put the outcome in
`unsupported_targets` with its actual data type, `reason_code` equal to
`insufficient_planning_basis`, and a precise reason.

For unsupported data shapes use `reason_code` equal to
`unsupported_data_type`. Every unsupported item contains `outcome_label`,
`data_type`, `reason_code`, and `reason`.

An overall analysis has null `subgroup_factor` and `subgroup_level`. Never use
`overall` or `all participants` as a subgroup level. For a prespecified
subgroup analysis, emit one overall target and separate targets for each real
factor/level pair with otherwise identical analysis semantics.

For every real subgroup target, set `subgroup_scope` to `study_level` when
whole studies are assigned to levels (for example geographical region or study
design), or `participant_level` when participants inside a study are split by
a characteristic (for example sex or a prespecified age band). For
`study_level`, set `subgroup_membership_relation` to `not_applicable`. For
`participant_level`, use `mutually_exclusive` only when the definitions in the
question or screening criteria make it impossible for one participant to
enter both levels. Otherwise use `overlapping` or `unknown`. Do not infer
membership independence from anticipated article results. Participant-level
subgroup difference testing currently supports exactly two explicitly
mutually exclusive levels; other levels may still be planned and summarized
separately but will not receive a formal interaction test.

`analysis_population_priority` refers to the statistical analysis set, such
as intention-to-treat, modified intention-to-treat, per-protocol, as-treated,
or a safety population. It is not the review's clinical population or a
subgroup. For an assignment effect, normally prioritize intention-to-treat
over modified intention-to-treat and per-protocol/as-treated results. For an
adherence effect or a safety outcome, use the analysis-set ordering supported
by that target's stated purpose. Explain the choice in
`decision_basis.analysis_population`; do not add an estimand object.

Prefer direct arm-level statistics usable by the planned effect measure.
Prefer the primary complete report and primary results source, while retaining
explicit lower-priority fallbacks. Never choose a result using effect size,
direction, statistical significance, P value, confidence interval, or
numerical completeness. Do not emit heterogeneity, confidence-interval,
prediction-interval, zero-event, missing-data, within-study action, or fallback
defaults. Those technical decisions and fixed business invariants belong to
later stages. Never invent study IDs, observed result settings, sample sizes,
or evidence availability.
