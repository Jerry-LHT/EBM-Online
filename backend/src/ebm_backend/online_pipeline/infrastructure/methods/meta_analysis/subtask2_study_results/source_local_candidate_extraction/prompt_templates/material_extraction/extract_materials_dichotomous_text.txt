Task
Read one narrative article text source and extract numeric materials for one
article-local dichotomous result candidate.

Stage responsibility
The candidate was already proposed from article evidence. This stage reads the
provided text source and returns numeric materials that belong to, or may
support, that candidate.

This stage may do source-grounded constrained inference from text when the text
explicitly states a numeric relation. The goal is to convert text evidence into
usable materials, not to decide final meta-analysis fields.

Do not rediscover candidates. Do not decide final meta-analysis fields. Do not
perform free inference. Do not use medical or trial-design assumptions that are
not stated in the source. Do not calculate from ambiguous relations. Do not
normalize article labels. A material must contain a numeric value or a numeric
source expression. Pure semantic text without a numeric expression is not a
material.

Input meaning
- `candidate` describes the article-local result setting currently being
  completed.
- `field_need_context` lists downstream fields and value contracts. Use it only
  to understand what kinds of numeric materials may be useful.
- `source` is one narrative text source from the article.

How to use the candidate
Use the candidate as the semantic scope for this source. Before extracting a
material, decide whether the numeric statement or numeric relation belongs to
the same outcome/event category, arm/comparator, population, timepoint,
subgroup, and denominator frame as the candidate.

If the text clearly refers to a different outcome, severity category,
population, timepoint, subgroup, arm, or denominator frame, do not treat that
number as direct for this candidate.

How to read this text source
Read the text as article evidence, not as a table. First identify direct numeric
statements relevant to the candidate. Then identify explicit numeric relations
that may support the candidate, such as:
- a total population split across arms;
- a remaining group implied by a stated total and one stated subgroup or arm;
- events, non-events, percentages, or rates tied to a clearly stated
  denominator or analysis population;
- analyzed, randomized, safety, follow-up, or outcome-assessed populations when
  the text explicitly distinguishes them.

Preserve the article's own wording for event labels, arms, populations,
timepoints, subgroups, and denominator descriptions.

Inference boundary
You may return an inferred material only when the text makes the relation
explicit enough that the missing numeric value follows directly from the stated
numbers and stated grouping. If there is any meaningful ambiguity about arm
structure, analysis population, timepoint, subgroup, denominator basis, or
which group the remainder belongs to, do not infer the missing value.

If the relation is explicit, you may infer materials such as:
- one arm total from an explicitly stated overall total and the other arm total;
- a non-event count from an explicitly stated arm total and event count for the
  same analysis population;
- a missing arm count when the text explicitly states that the remainder belongs
  to that arm.

If the relation is not explicit, keep only the direct numeric materials and
record any uncertainty in `warnings` or `source_meaning`.

Numeric material boundary
Extract dichotomous numeric materials such as event counts, arm totals,
denominators, overall totals, percentages, rates, non-event counts, and
person-time values.

A percentage is a percentage material, not an event count. Do not convert a
percentage into a count unless the source explicitly provides the denominator
and the relation needed for that conversion is explicit. Do not invent a
denominator. Do not infer a total, event count, or non-event count from vague
language.

Compound source expressions may be split when the source directly expresses
multiple numeric materials, such as `5/244 (2.0%)`. In that case, preserve the
source expression in `value_text` and describe each extracted value's role.

Interpreting numeric notation
Use this priority when deciding what a numeric expression means:
1. Source-explicit meaning: the sentence, paragraph, methods, or nearby wording
   explicitly defines the count, denominator, percent, or rate. This always
   wins.
2. Source-context meaning: nearby article text makes the numeric identity clear
   enough, even if the exact phrase does not repeat it.
3. Reporting convention: if the source gives no explicit or contextual
   definition and there is no conflicting signal, use common biomedical
   reporting conventions with medium or low confidence and state this basis in
   `source_meaning` or `warnings`.
4. Unclear: if several interpretations remain plausible, mark the role as
   `unclear`.

Common dichotomous reporting conventions:
- `a of b`, `a/b`, and `a (p%)` in an event statement usually provide event
  count plus denominator or percentage.
- A percentage is not an event count. It may support later calculation only
  when the matching denominator and scope are clear.
- Statements such as no events or no serious adverse events can support
  event count 0 only when the arm, event/category, and population scope are
  clear.
- Rates, person-time values, odds ratios, risk ratios, hazard ratios, and their
  intervals are not arm-level events or totals.

Source-grounding requirements
- Preserve source wording for event labels, arms, populations, timepoints, and
  denominator descriptions.
- `source_meaning` should state what the number means in the article, not just
  where it appears.
- `source_ref.quote_or_anchor` should be a short source-grounded quote around
  the numeric expression or relation.
- Use `candidate_relevance: "direct"` only when the value belongs to the
  candidate's local result.
- Use `candidate_relevance: "supporting"` when the value belongs to the same
  candidate context but mainly helps interpret, derive, or validate another
  material.
- Use `candidate_relevance: "contextual"` when the value is nearby and may be
  useful context, but is not itself the candidate's local result.
- For inferred materials, make it explicit in `source_meaning` that the value is
  inferred from an explicit textual relation and state that relation.
