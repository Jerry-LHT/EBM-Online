Task
Recover source-grounded numeric materials from one text source for the currently
open dichotomous-result needs.

This is an open-need-first task, not a whole-candidate matching task. Start from
`open_needs`. Do not first decide whether the source as a whole matches a
candidate.

Stage responsibility
- For each open need, determine what numeric material role could help resolve
  that missing field.
- Read the text and return direct, supporting, or intermediate numeric materials
  for those open needs.
- Return source-context materials when they can help a missing field, even if
  they are not endpoint event values.
- Source-grounded constrained inference is allowed only when the text explicitly
  states the numeric relation.
- Do not rediscover candidates.
- Do not decide final result fields.
- Do not calculate final meta-analysis values.
- Do not generate engineering ids.

Input meaning
- `open_needs` defines this task. Each item names a missing field, its value
  contract, and `field_semantics`.
- `field_semantics` states the target arm, material role, target meaning, and
  match context for that specific missing field. Use it instead of inferring
  field meaning from the field name alone.
- `field_semantics.required_match_context` contains the context that must match
  this missing field.
- `field_semantics.conditional_match_context` is auxiliary context. Use it as a
  required match only when `field_semantics.conditional_rule` says it applies
  and the source wording supports that condition.
- `source` is one text source. Treat the source wording as evidence.

Open-need workflow
For each item in `open_needs`:
1. Identify the target field.
2. Read `field_semantics` to determine the required material role and target
   arm.
3. Use `field_semantics.required_match_context` as the required match boundary
   for that material role.
4. Use `field_semantics.conditional_match_context` only under the stated
   conditional rule.
5. Inspect numeric expressions and explicit numeric relations in the text.
6. Return a material when its source meaning supports the open need and does
   not conflict with the role-specific constraints.

Dichotomous field roles
- `*_events`
  - role: event count for the candidate event/category.
  - constraints: compatible event/category, arm, timepoint or follow-up window,
    population or subgroup, denominator basis, and sample frame.
- `*_total`
  - role: denominator, sample size, analysis population, or sample frame for
    the candidate arm.
  - constraints: compatible arm, population or sample frame, denominator basis,
    and unit of analysis.
  - event/category and timepoint constrain this role only when the source says
    the denominator is event-specific or timepoint-specific.

Numeric source roles
For every numeric expression, first determine what it means in the text:
- event count;
- denominator or sample frame;
- percentage or rate;
- non-event count;
- supporting input for derivation;
- descriptive measurement;
- test statistic or p-value;
- unclear.

Use source role to decide whether a number can support an open need. A
descriptive measurement cannot fill an event-count field. A percentage or rate
is not an event count, but may support later calculation when its denominator
meaning is source-grounded. A denominator or sample-frame number is not an
event measurement; evaluate it by arm, population/sample frame, denominator
basis, and unit of analysis.

Interpreting numeric notation
Use this priority when deciding what a numeric expression means:
1. Source-explicit meaning: the sentence, paragraph, methods, or nearby wording
   explicitly defines the count, denominator, percent, or rate. This always
   wins.
2. Source-context meaning: nearby article text makes the numeric identity clear
   enough, even if the exact phrase does not repeat it.
3. Reporting convention: if the source gives no explicit or contextual
   definition and there is no conflicting signal, use common biomedical
   reporting conventions with medium or low confidence and state this basis in
   `source_meaning` or `warnings`.
4. Unclear: if several interpretations remain plausible, mark the role as
   `unclear`.

Common dichotomous reporting conventions:
- `a of b`, `a/b`, and `a (p%)` in an event statement usually provide event
  count plus denominator or percentage.
- A percentage is not an event count. It may support later calculation only
  when the matching denominator and scope are clear.
- Statements such as no events or no serious adverse events can support
  event count 0 only when the arm, event/category, and population scope are
  clear.
- Rates, person-time values, odds ratios, risk ratios, hazard ratios, and their
  intervals are not arm-level events or totals.

Source-context totals
Arm-level group size, sample size, participant count, denominator, or analysis
population can be useful material for a `*_total` open need even when it appears
in baseline, demographic, characteristics, eligibility, flow, methods, or other
non-endpoint text. Do not reject such a value only because the text is not
reporting endpoint events. Reject it only when its arm, population/sample frame,
denominator basis, or unit of analysis conflicts with the open need, or when
the source meaning is unclear.

Constrained inference from text
You may return an inferred material only when the text makes the relation
explicit enough that the value follows directly from stated numbers and stated
grouping. This is for materializing source evidence, not for final field
calculation. Do not infer when arm structure, population, timepoint,
event/category, denominator basis, sample frame, or the meaning of a remainder
is ambiguous.

Intermediate materials
Return intermediate materials when they may help Resolution or a deterministic
calculator, including percentages, rates, totals, non-event counts, p-values,
and other source-grounded denominator inputs. Do not calculate final result
fields in this stage.

Text reading
- Use the sentence, nearby sentences, paragraph heading, and source wording to
  identify what each number means.
- Preserve source wording for event/category, arm, timepoint, population,
  subgroup, denominator, and sample frame.

Empty output
If no numeric expression can support any open need, return `status: "empty"`.
If you saw numeric values that may look related, add a warning stating what you
saw and why they were not returned.
