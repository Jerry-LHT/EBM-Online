Task

Read one study source and identify the article-local result settings in this
source that may contribute study-level result data for a meta-analysis under
the given review analysis setting.

Stage responsibility

This stage only discovers source-local result settings and judges their
semantic relationship to the review analysis setting.

Do:
- identify result settings that are actually expressed in the source;
- preserve the source's own wording and granularity;
- return all compatible source-local settings, not only the best or most
  complete one;
- judge each returned setting as matched or possible;
- return only structured JSON.

Do not:
- extract numeric values or numeric materials;
- calculate, derive, or recover missing values;
- merge settings across sources;
- rewrite source labels into review-side labels;
- invent outcomes, timepoints, subgroups, or arm meanings not supported by the
  source;
- generate engineering ids, routing metadata, or trace fields.

Definitions

Review analysis setting:
the review-side target for this extraction task. It describes what the review
or meta-analysis is looking for, such as outcome, comparison, timepoint,
subgroup, and data type. Use it as semantic alignment context, not as a literal
string filter.

Reported result family:
the outcome, event, measurement, scale, subscale, component, or score family
reported in the source. Different named scales, subscales, total scores,
components, event types, or measurement instruments should remain separate
unless the source itself treats them as the same reported result family.

Article-local result setting:
one source-grounded result frame within a reported result family that a reviewer
could point to before extracting numbers for meta-analysis.

It is defined by the source's own reported meaning and frame, such as outcome
or event label, scale or component, visit or timepoint, population or subgroup,
statistic frame, and the arm set used for that result. It does not need to have
complete numeric data visible in this stage.

Source fidelity

Use source-grounded wording in `study_result_setting`. Do not replace source
labels with review labels. If the review setting and source label appear to
refer to the same concept, keep the source label in the setting fields and
explain the alignment in `alignment_rationale`.

For tables, read the raw table XML directly. Do not normalize, rewrite, or
clean the table structure before deciding the source-local settings.

How to identify candidates

1. Read the source and identify reported result families that are semantically
   compatible with the review analysis setting.
2. Within each compatible family, enumerate the source-local result settings
   expressed by the source.
3. Return each compatible source-local setting separately when the source
   distinguishes it.

Source-local settings may differ by:
- outcome, event category, scale, subscale, component, score, or instrument;
- visit, cycle, week, month, endpoint, baseline, follow-up, or change-from-
  baseline frame;
- population, subgroup, severity level, sample frame, or analysis set;
- statistic frame, such as post-treatment value, change score, event
  proportion, rate, adjusted estimate, or model-based estimate;
- source-expressed arm set or comparison frame.

If the review setting is broad and the source reports several narrower
compatible settings, return the narrower settings as separate candidates. Do
not choose only one representative, final, summary-like, or numerically
complete setting.

How to use the review analysis setting

Start with semantic compatibility of the reported result family. If the source
family clearly represents a different outcome, event, measure, population, or
data type, do not return it.

After the family is compatible, use comparison, timepoint, subgroup, and data
type to decide whether a source-local setting is matched or possible. A
source-local setting can still be valid when it is narrower, more specific, or
uses different local wording than the review setting.

Use `extraction_hint`, when present, as auxiliary context for semantic
alignment. It may help interpret the review target, but it must not override
what the source actually reports.

Arm and comparison labels

Source reports may use local arm names, group codes, abbreviations, or short
labels. These labels are not required to literally match the review comparison.
Preserve the source-local arm labels.

If the source defines local arm labels, use that definition for semantic
alignment. If the source does not define them clearly but the outcome family,
data type, and result frame are otherwise compatible, return the setting as
possible instead of excluding it for arm-label mismatch.

Do not split one result setting into separate candidates only because arms are
shown in separate rows or columns. If the arms share the same outcome,
timepoint, subgroup or population, and statistic frame, keep them in one
candidate and put the source-local arm labels in the arm fields.

Only exclude an arm set when the source makes a clear semantic conflict with
the review setting.

Match status

- matched:
  the source-local setting belongs to a compatible reported result family and
  the source frame has no clear conflict with the review analysis setting.

- possible:
  the source-local setting belongs to a compatible reported result family, but
  the review setting is broader, local arm labels are not fully mapped, or the
  source reports multiple narrower sibling settings that remain plausible under
  the review setting.

Only output matched or possible candidates. If a setting is clearly unrelated
or conflicting, omit it.

What not to return

Do not return:
- background, rationale, eligibility, or methods text without a reported result
  setting;
- pure outcome definitions without a source-local result frame;
- intervention descriptions without a result setting;
- discussion-only interpretations;
- section labels or navigation cues by themselves.

Output requirements

- `brief_summary` should briefly describe the relevant result content in this
  source.
- `study_result_setting` should use source wording and source-local
  granularity.
- `study_local_note` should explain what distinguishes this candidate from
  sibling settings in the same source.
- `alignment_rationale` should explain why this candidate is matched or
  possible.
- `uncertainties` should list unresolved source-grounded ambiguities only.

Return only JSON
