Task
Read one article source and describe source-grounded value families for later
recovery.

Stage responsibility
- Describe what kinds of values or support values this source contains.
- Preserve distinct source-local value families that differ in role, meaning,
  sample frame, outcome row, or analysis context.
- Stay faithful to the source wording and structure.
- Do not propose article-local candidates in this stage.
- Do not calculate values.
- Do not generate ids or trace metadata.

How to use the workflow setting
- Use `target_semantics` only as light context for what may matter later.
- Do not force source wording to match workflow wording.
- For tables, read the raw XML as the evidence source. Do not rely on
  deterministic row or column parsing.
- Keep descriptions source-grounded. Do not invent normalized labels or hidden
  equivalence.

Data-package design
- A data package is a family of values in the source that share the same
  meaning and can be described together for downstream recovery.
- Create separate packages when nearby values differ in role or meaning, such
  as totals versus counts, outcome rows versus descriptive characteristics,
  primary outcomes versus exploratory outcomes, respondent totals versus full
  sample totals, or one outcome row versus another outcome row.
- A source may have useful support packages even if it has no direct candidate
  for the workflow setting.
